## 为什么要搭建个人博客

一句话：**积淀价值**。

脑中的想法会消失，写下的文字不会——记录是留存思想与经验的手段。

思绪是网状的，文章是线性的——表达促使想法变得清晰。

如果这些价值还能传递出去，启发他人、链接同频者，那就再好不过了。

## 让 Fuwari 模板在本地运行

首先，能够简单使用 Git 、Github 和 VSCode 是最基本的前置条件。

如果你想搭建一个个人博客，有两种基本路径：

- 一是挑选一个合适的框架，自己从零开始写。在有 AI 辅助的当下，这也不会特别困难。优点是能够完全按照自己的想法来，深度定制需求。缺点是可能会略显麻烦。
- 二是使用一个现成的模板，这也是我采用的方式。这样你可以很方便地搭建好自己的博客。当然，如果你想在此基础上自己修改也是完全可以的，我后面的文章也会讲自己是如何修改的。

[Fuwari](https://github.com/saicaca/fuwari) 是 saicaca 大佬基于 [Astro](https://github.com/withastro/astro) 框架开发的一款个人博客模板，被广泛地使用和二改。我比对了很多个人博客模板，最终决定使用 Fuwari 作为模板，再根据自己的需求进行一些修改。

### 创建仓库并克隆到本地

你可以选择 Fork [Fuwari](https://github.com/saicaca/fuwari) 这个仓库或者直接 [点这里](https://github.com/new?template_name=fuwari&template_owner=saicaca) 使用 Fuwari 模板生成新仓库。

然后使用 git 命令或者在 VSCode 中把刚刚生成的仓库 clone 到本地。

### 安装依赖

在命令行中输入：

```bash
node -v
```

如果未显示版本号，那么你需要先安装 [Node.js](https://nodejs.org/zh-cn) ，安装成功后再输入该命令会显示版本号。

安装 pnpm（比自带的 npm 更好的 Node.js 包管理器）：

```bash
npm install -g pnpm
```

在项目根目录使用 pnpm 安装项目依赖：

```bash
pnpm install
pnpm add sharp
```

你还可以按需给 VSCode 安装 Astro 、Biome 、Markdown All in One 等插件方便后续开发。

### 本地部署

接下来在本地启动服务器：

```bash
pnpm dev
```

命令行会输出本地服务器的地址（通常是 http://localhost:4321/ ），在浏览器访问就能预览网页效果了。

Astro 框架支持热重载。这意味着你对代码做出修改并保存后，浏览器页面会自动变更。你无需重新启动服务器，甚至不需要手动刷新页面。

## 个人博客的基础配置

现在你看到的网页只是个模板，要让它成为自己的个人博客，个性化配置是必不可少的。

### 文件结构简介

仓库里面纷繁复杂的文件一定看得你眼花缭乱。其实，你真正需要修改的只是其中的少数几个。哪怕你要进行较大的修改，大部分的文件也是不需要动的。

根目录下你可以先关注：
- `README.md` ：你的仓库的说明。
- `public/` ：专门用于存放不需要 Astro 进行任何处理的静态资源。里面目前只有存放网站图标用的 `favicon/` 文件夹。
- `src/` ：存放了项目的核心源代码。

`src/` 目录下你可以先关注：
- `content/` ：存放网站具体内容的核心文件夹。其中：
  - `posts/` 文件夹中的所有 `.md` 和 `.mdx` 文件都会被 Fuwari 识别并处理为博客文章，你可以根据需要自由地在其中创建目录来分类管理自己的文章和与之相关的图片等资源。里面已经存放了几篇默认文章。
  - `spec/` 文件夹用于存放博客中非文章的独立页面，默认只有一个 About 页面，你可以在博客的顶部看到。
- `layouts/` ：存放布局组件，即页面模板，为多个页面提供可复用的 UI 结构。有需要可以在这里进一步修改页面布局。
- `components/` ：存放项目中所有可复用的 UI 组件。有需要可以修改。
- `pages/` ：Astro 项目中的核心文件夹。导入内容和组件，直接决定网站的页面。其中的路径直接对应网页地址。
- `config.ts`（注意是 `src/` 目录下的，不是 `content/` 目录下的）：网站的配置文件，也是接下来需要修改的重点。

### 网站基础配置

编辑 `config.ts` 来完成网站的基础配置。

```ts title="config.ts"
import type {
	ExpressiveCodeConfig,
	LicenseConfig,
	NavBarConfig,
	ProfileConfig,
	SiteConfig,
} from "./types/config";
import { LinkPreset } from "./types/config";

/**
 * 站点全局配置
 * 包括网站标题、副标题、语言、主题颜色、横幅图片、层级目录以及网站图标等基础信息。
 */
export const siteConfig: SiteConfig = {
	// 基础设置
	title: "网站标题",
	subtitle: "网站副标题",
	lang: "zh_CN", // 语言改成中文
	// 主题颜色
	themeColor: {
		hue: 250, // 主题颜色的默认色相（0-360）
		fixed: false, // 是否对访客隐藏主题颜色选择器
	},
	// 网站顶部的横幅图片
	banner: {
		enable: false,
		src: "assets/images/bg.png", // 不以 '/' 开头，表示相对于 /src 目录。如果以 '/' 开头，则表示相对于 /public 目录。后续目录表示全部同理
		position: "center", // 控制选取图片的哪个区域，仅支持 'top'、'center'、'bottom'
		credit: {
			enable: false, // 是否显示
			text: "", // 署名文本
			url: "", // （可选）指向原始艺术作品或作者页面的 URL 链接
		},
	},
	// 层级目录（Table of Contents）
	toc: {
		enable: true, // 是否在文章右侧显示层级目录
		depth: 2, // 目录中显示的最大标题层级（1-3）
	},
	// 网站图标
	favicon: [
		// 留空此数组以使用默认 favicon
		// {
		//   src: '/favicon/icon.png',    // favicon 路径，相对于 /public 目录
		//   theme: 'light',              // （可选）'light' 或 'dark'，仅在浅色和深色模式使用不同 favicon 时设置
		//   sizes: '32x32',              // （可选）favicon 尺寸，仅在有不同尺寸 favicon 时设置。推荐放入多个尺寸的 favicon ，可以使用相关工具生成
		// }
	],
};

/**
 * 导航栏配置
 * 定义页面顶部导航栏中显示的链接，支持内置预设（首页、归档、关于）以及自定义外部链接。
 */
export const navBarConfig: NavBarConfig = {
	links: [
		LinkPreset.Home,
		LinkPreset.Archive,
		LinkPreset.About,
		{
			name: "GitHub",
			url: "https://github.com/saicaca/fuwari", // 内部链接不应包含 base 路径，因为会自动添加
			external: true, // 显示外部链接图标，并将在新标签页中打开
		},
	],
};

/**
 * 个人资料配置
 * 设置博客侧边栏或作者卡片中展示的头像、姓名、简介以及社交链接列表。
 */
export const profileConfig: ProfileConfig = {
	avatar: "assets/images/avatar.png",
	name: "name",
	bio: "bio",
	links: [
		{
			name: "QQ",
			icon: "fa6-brands:qq", // 访问 https://icones.js.org/ 获取图标代码。如果尚未包含对应的图标集，则需要安装`pnpm add @iconify-json/<图标集名称>`
			url: "https://qm.qq.com/q/*",
		},
		{
			name: "Email",
			icon: "material-symbols:mail",
			url: "mailto:*@qq.com",
		},
		{
			name: "Bilibili",
			icon: "fa6-brands:bilibili",
			url: "https://space.bilibili.com/*",
		},
		{
			name: "GitHub",
			icon: "fa6-brands:github",
			url: "https://github.com/*",
		},
	],
};

/**
 * 许可证配置
 * 用于文章页脚的版权声明，可启用并指定许可证名称和对应的 URL。
 */
export const licenseConfig: LicenseConfig = {
	enable: true,
	name: "CC BY-NC-SA 4.0",
	url: "https://creativecommons.org/licenses/by-nc-sa/4.0/",
};

/**
 * 代码高亮主题配置
 * 设置博客中代码块的高亮主题。
 */
export const expressiveCodeConfig: ExpressiveCodeConfig = {
	// 注意：部分样式（如背景颜色）被覆盖，请参见 astro.config.mjs 文件
	theme: "github-dark",
};
```

你还可以在 `src/constants/constants.ts` 中调整横幅图片尺寸、页面宽度等参数。

完成了这些配置后，这个网站才真正地成为了你的个人博客。

## 部署到互联网

要让全世界都看到你的网页，需要把仓库部署到服务器上。你当然可以自己花钱买一台服务器。不过，免费的静态网站托管平台显然是更具性价比的选择。

[Vercel](https://vercel.com/) 、[Netlify](https://www.netlify.com/) 、[GitHub Pages](https://docs.github.com/pages) 等平台都可以选择，你可以自行了解它们之间的优劣。你可以参考 Astro [官方指南](https://docs.astro.build/zh-cn/guides/deploy/) 来完成部署。通常你只需要在你选择的平台使用 GitHub 账号登录，然后导入你的仓库，平台就能自动构建并发布了。构建成功后，你的博客就会获得一个在线的访问地址，让全世界的人都能访问你的个人博客。

当然，这种情况下你的博客的域名一般是你选择的平台的子域名。如果你想拥有一个定制的网址，也可以选择自己购买一个合适的域名，然后将域名绑定到你的服务器上。
